# Лоадаут → Tool-слоты, удар → сервер

Схема для игр, где набор предметов игроку выдаёт сервер (ролл, класс, кит), а бой ближний.
Клиент ни предмета, ни попадания не решает: он получает Tool и шлёт факт клика.

## Слоты как Tool

| Что | Как |
| :--- | :--- |
| Слот | `Tool` без модели: `RequiresHandle = false`, `CanBeDropped = false` |
| Кто создаёт | Сервер, в `Backpack`, в порядке слотов; первый — `Humanoid:EquipTool` |
| Как узнать слот | Атрибуты на Tool: `Slot` (Weapon/Ability/Magic), `ItemId`, `Effect` |
| Когда | По сигналу владельца лоадаута `LoadoutChanged(player, loadout | nil, record)` |
| Момент выдачи | Чистая функция от записи ролла: конец Reveal, не `task.wait` в обработчике |
| Сгорание | Тот же сигнал с `nil`: снести Tool из Backpack и из персонажа |

Гонка «выдача уже запланирована, а игрок умер»: номер выдачи на игрока (`generation`), отложенная
раздача сверяет свой номер перед тем, как класть Tool. Взаимоисключение оружия и способности
приходит бесплатно — штатный рюкзак держит в руке один Tool.

## Удар

```text
клик → Tool.Activated (клиент) → своя проверка такта → замах локально → AttackRequest
сервер: гейт → жив, в руке Tool со слотом Weapon и ItemId == loadout.weapon → такт → Ok/Denied
        task.delay(HitDelay) → GetPartBoundsInBox перед корнем → один Humanoid на модель → TakeDamage
```

- Проверять **Tool в руке против лоадаута сервера**, а не верить атрибуту: клиент Tool не создаёт,
  но подменить экипировку через эксплойт может.
- Клиент играет клип сам: трек на Animator собственного персонажа реплицируется соседям без пакетов.
- `AttackResult` со статусом на **каждый** запрос; на `Denied` клиент снимает замах и сбрасывает такт.
- Один `OverlapParams` на модуль, `ExcludeInstances = { character }` на удар, `MaxParts` ограничен.
- `HitDelay < SwingDuration`, `Interval` короче клипа — серия идёт внахлёст, а не ждёт конца.
- Допуск на сеть (`SwingTolerance` ≈ 50 мс) в серверной проверке такта: клиент бьёт по своим часам.

## Запрет параллельного действия на время замаха

Замах запирает ролл/каст одним окном `busyUntil`: новый замах двигает конец окна, отложенный
`task.delay` снимает запрет только если его окно всё ещё последнее. Сеттер запрета не шлёт пакет,
если значение не изменилось, — иначе серия ударов льёт по два пакета на замах.

## Чистая часть — в общий модуль и под спек

`familyOf(itemId)`, `canSwing`, `comboStep`, `hitBox`, `victims`, `slotsOf`, `equipAt` живут в
`ReplicatedStorage` и покрываются TestEZ: каждое оружие каталога попадает в семейство с клипами и
тактом, серия ходит по кругу и сбрасывается, бокс стоит перед корнем, цель считается раз на модель.

## Чеклист

- [ ] Tool создаёт сервер; клиент только слушает `Activated`
- [ ] Атрибуты слота на Tool, сверка с лоадаутом сервера в обработчике удара
- [ ] `generation` на игрока против гонки выдачи и смерти
- [ ] Ответ на каждый AttackRequest, отказ снимает замах на клиенте
- [ ] Один OverlapParams, дедупликация цели по модели, мёртвые не в счёт
- [ ] Числа боя в конфиге с пометкой «заглушка», клипы греются `PreloadAsync` всем пулом
- [ ] Спек на чистые функции; таблицы за игрока чистятся в `PlayerRemoving`

## Антипаттерны

- Урон по `Tool.Activated` на сервере или по `.Touched` — нет гейта, нет такта, нет сверки
- `Handle`-модель ради экипа: без модели Tool работает, а модель приедет отдельной задачей
- Замах на сервере через `Animator` персонажа игрока — не реплицируется владельцу
- `SetBlocked(true/false)` на каждый удар без коалесценции — пакет на каждый клик
- Раздача Tool прямо в обработчике сигнала с `task.wait` — умерший игрок получит набор

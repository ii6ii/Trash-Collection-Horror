# Блоки-держатели выше прыжка

## Проблема

Препятствие держит игрока своей геометрией — и по склону он поднимается пешком (движок пускает на любой уклон), с макушки перепрыгивает на соседнее и бежит поверху, минуя механику (рубку, лабиринт). Стена ровно по высоте прыжка тоже не спасает: с макушки соседнего препятствия прыжок начинается выше.

## Правило

Держит не геометрия, а отдельный невидимый блок. Его верх выше, чем достаёт прыжок **с макушки самого препятствия**:

```text
JumpHeight = JumpPower² / (2 × Gravity)
JumpClear  = JumpHeight + запас на шаг и неровности пола (≈2 studs)
Block      = высота препятствия + JumpClear
```

Числа живут в одном конфиге (`WorldConfig`): `Gravity`, `JumpPower`, `JumpHeight`, `JumpClear`. Их читают и сервер, и клиент, и инструменты сборки уровня.

## Реализация

| Шаг | Что делать |
| :--- | :--- |
| Конфиг | `WorldConfig.JumpPower` дублирует `StarterPlayer.CharacterJumpPower` — свойство места в код не приезжает. `JumpHeight` и `JumpClear` выводятся формулой, не пишутся руками |
| Тест | В спеке сравнить `StarterPlayer.CharacterJumpPower` с `WorldConfig.JumpPower` и `JumpHeight` с пересчётом по `Gravity`. Разойдутся — на препятствие снова можно запрыгнуть |
| Блок | `Part`: `Anchored`, `CanCollide = true`, `CanQuery/CanTouch = false`, `Transparency = 1`, `CastShadow = false`. Низ вровень с препятствием, верх на `JumpClear` выше макушки: центр = центр препятствия + `yAxis × JumpClear / 2`, `Size.Y = высота + JumpClear` |
| Жизнь блока | Блок создаётся вместе с препятствием и уходит вместе с ним (тот же `Trove`). Переживший препятствие блок — невидимая стена посреди уровня |
| Клетки поля | Для сетки клеток (трава, кристаллы) один блок на живую клетку: `CellConfig.Block = Wall + JumpClear`. Снимается в момент среза, до анимации падения |

Блок прямоугольный: по углам круглого валуна игрок встаёт на шаг раньше геометрии. Цена видна только вплотную, круглый блок одной деталью не собрать.

## Визуал отдельно от держателя

Высота видимой стены (травы, кустов) выбирается по читаемости, а не по прыжку: по колено не читается стеной, в полный рост закрывает обзор на цель за ней. Держит игрока блок, стена только показывает границу. Разброс высоты узкий — рваный верх стену не читает.

## Где блоки не нужны

- Площадка высадки: вокруг точки спавна проплешина (`Clearing`) шире, чем у препятствий, — игрок садится с воздуха и не должен оказаться внутри блока.
- Чужие препятствия: состояние клеток локальное, блок клиентский — несрубленная трава соседа держать не должна.

## Чеклист

- [ ] `JumpPower` в конфиге равен `CharacterJumpPower` места, есть тест
- [ ] Высота блока считается от `JumpClear`, а не числом «с запасом»
- [ ] Блок и препятствие в одном `Trove`
- [ ] Блок снимается там же, где препятствие перестаёт быть препятствием (срез, слом)
- [ ] Проплешина вокруг спавна больше радиуса препятствия

## Антипаттерны

- Стена «чуть выше прыжка» без учёта прыжка с макушки соседа
- `CanCollide` на самой геометрии препятствия как единственный держатель
- Своё число высоты прыжка в каждом модуле
- Блок с `CanQuery = true` — ломает лучи прицела и подбора

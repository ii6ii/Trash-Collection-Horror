# Предсказание урона по клеткам

## Разделение ролей

| Сторона | Делает | Не делает |
| :--- | :--- | :--- |
| Сервер | HP клеток в сессии, слом, начисление, пакет `Fell(zone, index)` | визуал |
| Клиент | `Hit` по своему такту инструмента: вспышка, просадка, срез, блок-держатель | не решает, сломана ли клетка «по-настоящему» |

Картинка идёт по **своему** такту, а не по ответу сервера — иначе отстаёт от замаха на пол-задержки. Сектор, радиус и сила берутся теми же функциями и из той же реплики профиля, что на сервере (`CellField.wedge`, `RangeConfig`, `strength`). Расхождение = клетка приминается у одного и падает у другого.

`Fell` от сервера обычно приходит на уже открытую клетку и оказывается пустым вызовом; он же закрывает промахи предсказания (`zone.dead[index]` ставится в одном месте `_fell`).

## Состояние клеток

- Локальное: срубленное этим игроком другим не видно, и серверный инстанс так не спрятать. Ковёр общий — клетка **гасится** (`LocalTransparencyModifier = 1`), не удаляется.
- Просадка считается от **остатка HP**, не копится ударами: зона пересобирается окном вокруг игрока, накопленный в анимации спуск на пересборке потерялся бы.
- Поза покоя (`base`, `root`, `size`) снимается при **первом ударе** по клетке, один раз и навсегда: снять её со срезанной клетки второй раз — запомнить примятой.
- Держащий блок (см. `roblox-jump-clearance-blocks`) снимается в `_fell`, до анимации: с этого мига клетка «только картинка».

## Волна падения

Клетка срублена сразу, а ложится, когда до неё дойдёт волна от **точки замаха** (`_from` запоминается в `Hit`): `delay = min(distance / Wave.Speed, Wave.Hold)`. Выкос читается движением от игрока наружу, а не рядами мигающих клеток. Очередь `_falling` с `at = os.clock() + delay`; отрастание/разбор зоны снимают признак срубленности — очереди нечего ронять.

Срез ждёт, пока отыграется просадка до дна (`Sink.Deep`): у прокачанного игрока весь спуск приходится на этот миг, и его надо показать до пропадания.

## Пулы

Общий рецепт для осколков, подсветок (`Highlight`), любых «летящих» деталей:

```lua
-- свободный слот → новый, пока пул не набран → иначе старейший
for _, slot in pool do if slot.age >= Life then return slot end ... end
if #pool < Max then return create() end
return oldest
```

Порядок важен: сначала свободный, потом рост — иначе горящий слот находится всегда и пул не растёт. Потерять хвост дальнего разлёта дешевле, чем деталь на каждую клетку. Лимиты (`Shatter.Pool`, `FLASHES`) в конфиге с пояснением цены.

## Хрупкие биомы

`CellConfig.Brittle[band]`: удар отдаёт дрожью, срез — разлёт осколков из пула вместо оседания пружиной. Материал реплики звука отдаётся наружу (`"HitCrystal"/"HitGrass"`), играет вызывающий — в тот же такт мог попасть камень, и что главнее, знает он.

## Ресурс в месте

Имя образца (`CellConfig.Nodes.Cell[band]`) — ещё не образец. Промах по узлу в `Assets.ZoneProps` даёт пустую зону без единой ошибки. Обязателен спек: узел существует, класс `BasePart/Model/Folder`, папка не пуста. Проверка «строка в конфиге не nil» этого не закрывает.

## Чеклист

- [ ] `Hit` и сервер считают сектор одной функцией и одними константами
- [ ] `Fell` идемпотентен, `dead` ставится в одном месте
- [ ] Просадка от остатка HP, поза покоя снимается один раз
- [ ] Блок снимается на срезе, до анимации
- [ ] Пулы: свободный → новый → старейший, лимит в конфиге
- [ ] Тест на наличие образца в месте

## Антипаттерны

- Ждать ответ сервера, чтобы показать удар
- `Destroy()` общих деталей ковра
- Накопление визуального урона отдельно от HP
- `Instance.new` осколка на каждый срез

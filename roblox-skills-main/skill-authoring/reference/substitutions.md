## Инъекция shell-команд

Синтаксис `` !`команда` `` выполняется **до** отправки содержимого скилла модели: плейсхолдер заменяется выводом команды, и Claude получает готовые данные, а не команду.

```yaml
---
description: Резюмирует незакоммиченные изменения и отмечает рискованные места.
---

## Текущие изменения

!`git diff HEAD`

## Задача

Опиши изменения тремя пунктами, затем перечисли риски.
```

Многострочный вариант — блок кода, открытый ` ```! `:

````markdown
## Окружение
```!
node --version
git status --short
```
````

Важные ограничения:

- Инлайновая форма распознаётся, только если `!` стоит **в начале строки или сразу после пробельного символа**. Если перед ним другой символ (`KEY=!`cmd``), это остаётся обычным текстом и команда не выполняется. Этим удобно пользоваться, когда синтаксис нужно показать в тексте, а не выполнить.
- Подстановка проходит **один раз** по исходному файлу. Вывод команды вставляется как обычный текст и повторно не сканируется — команда не может сгенерировать плейсхолдер для следующего прохода.
- В скиллах, синхронизированных с аккаунта claude.ai, эти команды на машине пользователя не выполняются никогда.
- Настройка `"disableSkillShellExecution": true` отключает выполнение для пользовательских, проектных, плагинных скиллов и скиллов из дополнительных каталогов: команда заменяется на `[shell command execution disabled by policy]`.

## Как выполняются инъектированные команды

Оболочка выбирается по полю `shell` и окружению:

- `shell: powershell` при включённом инструменте PowerShell — команды идут через него.
- `shell: bash`, когда bash недоступен (Windows без Git Bash), — **вызов скилла падает целиком** с сообщением ``Skill <name> requires bash (`shell: bash` in frontmatter) but Git Bash was not found``.
- В остальных случаях — Bash, если он есть, иначе PowerShell.

Поведение совпадает с обычными shell-командами Claude:

- **Рабочий каталог** — текущий каталог сессии, который смещается, если Claude делал `cd`. Для путей, которые должны резолвиться одинаково всегда, используй `${CLAUDE_SKILL_DIR}` или `${CLAUDE_PROJECT_DIR}`.
- **stderr** при `bash` сливается в stdout и попадает в инъектированный текст.
- **Таймаут** — стандартные 2 минуты Bash-инструмента.
- **Объём вывода** сверх лимита приходит как путь к файлу с коротким превью.

## Что происходит при ошибке команды

Упавшая команда прерывает **весь вызов скилла**, а не только свой плейсхолдер: Claude не увидит содержимое скилла вообще. Сообщение — `Shell command failed for pattern "..."`, вывод команды идёт под `[stderr]`.

- При `bash` любой ненулевой код возврата считается ошибкой. Исключение: код 1 у поисковых и сравнивающих команд (`grep` и подобные) считается нормальным результатом; код 2 и выше валит вызов и у них.
- Для команд, которые штатно возвращают ненулевой код (например, скрипт проверки, выходящий с 1 при найденных проблемах), дописывай `|| true`.
- Инъектированные команды никогда не спрашивают разрешение. Если проверка permissions вернула что угодно кроме «разрешено» — включая правило, которое обычно показывает запрос, — вызов прерывается с `Shell command permission check failed for pattern "..."`. Лечится добавлением команды в `allowed-tools`; правило типа ask или deny прерывает вызов независимо от `allowed-tools`.

## Аргументы вызова

| Плейсхолдер | Значение |
| :--- | :--- |
| `$ARGUMENTS` | вся строка аргументов как введена |
| `$ARGUMENTS[N]` | аргумент по индексу с нуля |
| `$N` | сокращение для `$ARGUMENTS[N]`: `$0`, `$1`, … |
| `$имя` | именованный аргумент, объявленный в поле `arguments` |

```yaml
---
name: migrate-component
description: Переносит компонент с одного языка на другой.
---

Перенеси компонент $0 с $1 на $2. Сохрани поведение и тесты.
```

`/migrate-component SearchBar JavaScript TypeScript` подставит `SearchBar`, `JavaScript`, `TypeScript`.

- Индексные аргументы разбираются по правилам shell-кавычек: `/skill "hello world" second` даёт `$0` = `hello world`, `$1` = `second`.
- Индексный плейсхолдер без соответствующего аргумента остаётся в тексте как есть; именованный — раскрывается в пустую строку.
- Если аргументы переданы, но ни один плейсхолдер их не получил, Claude Code дописывает в конец содержимого `ARGUMENTS: <ввод>`.
- Значение аргумента, само содержащее `$1` или `$ARGUMENTS`, вставляется буквально и повторно не раскрывается.
- Можно составить цепочку скиллов в начале сообщения: `/write-tests /fix-issue 123` загрузит оба и передаст `123` каждому. Раскрывается первый скилл и до пяти следующих; цепочка обрывается на первом токене, который не является инлайновым user-invocable скиллом (например, на форкнутом `/code-review`).

## Переменные окружения скилла

| Переменная | Значение |
| :--- | :--- |
| `${CLAUDE_SKILL_DIR}` | каталог с `SKILL.md` этого скилла |
| `${CLAUDE_PROJECT_DIR}` | корень проекта |
| `${CLAUDE_SESSION_ID}` | id текущей сессии |
| `${CLAUDE_EFFORT}` | текущий уровень усилий: `low`, `medium`, `high`, `xhigh`, `max` |
| `${CLAUDE_PLUGIN_ROOT}` | каталог установки плагина (только в плагинных скиллах) |
| `${CLAUDE_PLUGIN_DATA}` | каталог данных плагина, переживающий обновления (только в плагинных) |

`${CLAUDE_SKILL_DIR}` и `${CLAUDE_PROJECT_DIR}` подставляются в двух местах: в теле скилла и в Bash-правилах поля `allowed-tools`. Одна и та же переменная в обоих местах позволяет запустить вложенный скрипт без запроса разрешения:

```yaml
---
name: render-chart
description: Строит график по CSV-файлу.
allowed-tools: Bash(${CLAUDE_SKILL_DIR}/scripts/render.sh *)
---

Запусти `${CLAUDE_SKILL_DIR}/scripts/render.sh <csv-file>` для построения графика.
```

## Экранирование

Чтобы вставить литеральный `$` перед цифрой, словом `ARGUMENTS` или именем объявленного аргумента, ставь обратный слеш: `\$1.00`. Экранирует только одиночный слеш непосредственно перед токеном; `\\$1` оставляет оба слеша и всё равно раскрывает `$1`.

Обратный слеш **не** отменяет подстановку переменных `${CLAUDE_*}` — их нельзя показать в теле скилла буквально. Если нужно продемонстрировать такой синтаксис в документации, выноси примеры в reference-файл: он читается инструментом Read, и подстановки к нему не применяются.

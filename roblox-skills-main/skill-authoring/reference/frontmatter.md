# Справочник полей frontmatter

## Содержание

- Все поля SKILL.md
- Совместимость со стандартом Agent Skills (вне Claude Code)
- Откуда берётся имя команды
- Управление видимостью через настройки

## Все поля SKILL.md

Все поля опциональны; рекомендуется как минимум `description`. Булевы поля принимают `true/false`, `yes/no`, `on/off`, `1/0` в любом регистре.

| Поле | Описание |
| :--- | :--- |
| `name` | Отображаемое имя в списках скиллов. По умолчанию — имя каталога. Для личных и проектных скиллов **не влияет** на имя команды; для плагинных задаёт последний сегмент команды. |
| `description` | Что делает скилл и когда применять. По нему Claude решает, подключать ли скилл. Если не задано — берётся первый абзац тела. Лимит поля 1024 символа; в листинге `description` + `when_to_use` обрезаются на 1536 символах, поэтому ключевой сценарий ставится первым. |
| `when_to_use` | Дополнительный контекст для автосрабатывания: триггерные фразы, примеры запросов. Дописывается к `description` и считается в общий лимит 1536. |
| `argument-hint` | Подсказка в автодополнении об ожидаемых аргументах, например `[issue-number]` или `[filename] [format]`. |
| `arguments` | Именованные позиционные аргументы для подстановки `$имя` в теле. Строка через пробел или YAML-список; имена сопоставляются позициям по порядку. |
| `disable-model-invocation` | `true` — Claude не может подключить скилл сам, только пользователь через `/имя`. Также исключает скилл из преднагрузки в сабагенты и из запуска по расписанию. По умолчанию `false`. |
| `user-invocable` | `false` — скилл может вызвать только Claude; из меню `/` он скрыт. Для фоновых знаний, которые не являются действием. По умолчанию `true`. |
| `allowed-tools` | Инструменты, разрешённые без запроса подтверждения на время хода, в котором вызван скилл. Грант снимается со следующим сообщением пользователя. Строка через пробел/запятую или YAML-список. |
| `disallowed-tools` | Инструменты, убираемые из пула, пока скилл активен. Снимается так же. Не может убрать `EndConversation`, пока остаются другие инструменты. |
| `model` | Модель на время действия скилла. Значения как у `/model`, либо `inherit`. С `context: fork` задаёт модель форкнутого сабагента. Не сохраняется в настройки — следующий промпт возвращает модель сессии. |
| `effort` | Уровень усилий: `low`, `medium`, `high`, `xhigh`, `max` (доступность зависит от модели). Перекрывает уровень сессии. |
| `context` | `fork` — запуск в изолированном сабагенте. |
| `agent` | Тип сабагента при `context: fork`: `Explore`, `Plan`, `general-purpose` или свой из `.claude/agents/`. По умолчанию `general-purpose`. |
| `background` | Только с `context: fork`. `false` — дождаться результата в том же ходу вместо фонового запуска. По умолчанию `true`. |
| `hooks` | Хуки, которые регистрируются при вызове скилла и работают до конца сессии. |
| `paths` | Glob-шаблоны, ограничивающие автосрабатывание файлами по маске. Строка через запятую или YAML-список. |
| `shell` | Оболочка для инъекции команд: `bash` (по умолчанию) или `powershell`. |
| `metadata` | Произвольная YAML-карта для своих данных. Claude Code её не интерпретирует. Не переиспользуй имена настоящих полей как ключи. |
| `license` | Лицензия скилла. Из спецификации Agent Skills; Claude Code принимает, но не использует. |
| `compatibility` | Требования к окружению, до 500 символов. Принимается, но не используется. |

## Совместимость со стандартом Agent Skills

Claude Code принимает все поля выше. Но при загрузке скилла на claude.ai, через Skills API или при упаковке `package_skill.py` допустимы только шесть полей спецификации:

`name`, `description`, `license`, `compatibility`, `metadata`, `allowed-tools`

Любое другое поле там — жёсткая ошибка, а не игнор:

```
Unexpected key(s) in SKILL.md frontmatter: argument-hint. Allowed properties are: allowed-tools, compatibility, description, license, metadata, name
```

Функции тела, специфичные для Claude Code (инъекция команд, подстановки), в чате claude.ai и через API не работают. Скилл, ограниченный шестью полями спецификации, при этом грузится в Claude Code без изменений.

Это же ограничение действует, когда личный скилл включается для Cowork и облачных сессий, — он туда загружается через claude.ai.

## Откуда берётся имя команды

| Расположение скилла | Источник имени | Пример |
| :--- | :--- | :--- |
| `~/.claude/skills/` или `.claude/skills/` | имя каталога | `.claude/skills/deploy-staging/SKILL.md` → `/deploy-staging` |
| Вложенный `.claude/skills/` при конфликте имён | путь подкаталога + имя каталога скилла | `apps/web/.claude/skills/deploy/SKILL.md` → `/apps/web:deploy` |
| Файл в `.claude/commands/` | имя файла без расширения | `.claude/commands/deploy.md` → `/deploy` |
| Подкаталог `skills/` плагина | `name` или имя каталога, с префиксом плагина | `my-plugin/skills/review/SKILL.md` → `/my-plugin:review` |
| `SKILL.md` в корне плагина | `name`, иначе имя каталога плагина | `name: review` → `/my-plugin:review` |

Скиллы также подхватываются из `.claude/skills/` во всех родительских каталогах вплоть до корня репозитория. Вложенные (ниже рабочего каталога) загружаются не на старте, а в момент, когда Claude впервые читает или правит файл в этом подкаталоге.

## Управление видимостью через настройки

`skillOverrides` в `.claude/settings.local.json` управляет видимостью, не трогая сам SKILL.md (полезно для скиллов из общего репозитория). В меню `/skills` состояние переключается пробелом.

| Значение | Видно Claude | В меню `/` |
| :--- | :--- | :--- |
| `"on"` | имя и описание | да |
| `"name-only"` | только имя | да |
| `"user-invocable-only"` | скрыт | да |
| `"off"` | скрыт | скрыт |

```json
{
  "skillOverrides": {
    "legacy-context": "name-only",
    "deploy": "off"
  }
}
```

Отсутствие скилла в `skillOverrides` равнозначно `"on"`. На плагинные скиллы настройка не действует — ими управляет `/plugin`.

## Если описания обрезаются

Листинг имён и описаний всех скиллов лежит в контексте постоянно, его бюджет — 1% окна контекста. При переполнении описания урезаются, начиная с наименее используемых скиллов, и Claude теряет ключевые слова для сопоставления.

- `/doctor` показывает оценку стоимости листинга и главных потребителей.
- `skillListingBudgetFraction` (например `0.02`) поднимает бюджет; `skillListingMaxDescChars` меняет потолок 1536.
- `"name-only"` в `skillOverrides` освобождает бюджет под важные скиллы.

# Слоты с окном множителей по прогрессии

Счётчик прогрессии только растёт — значит, всё, что от него зависит, в профиль не пишется, а считается.

## Контракт

| Что | Где живёт | Почему |
| :--- | :--- | :--- |
| Лестница множителей | Формула в конфиге (первый, шаг, длина) | Баланс-проход правит числа, а не таблицу из N строк |
| Открыт ли слот | `count >= Unlock[slot]` | Счётчик не убывает — слот не закроется, миграций нет |
| Сдвиг окна | `clamp(count - Unlock[shiftSlot] + 1, 0, ladder - slots)` | Один сдвиг на открытии, по одному дальше, стоп в конце лестницы |
| Множитель стенда | `ladder[shift + slot - 1]` | Скин идёт за множителем, а не за стендом |
| Купленные донатные | Множество в профиле `{ ["k"] = true }` | Разрежённый числовой массив схлопывается при сохранении |
| Множитель в заезде | Снимок при посадке | Сброс прогрессии посреди сессии не меняет уже начатое |

Проверка формулы сдвига — табличный тест на весь диапазон счётчика: «открытие даёт ровно +1, а не +2»
и «после конца лестницы без изменений» ловятся только так.

## Сервер

1. Одна чистая модель (`coef`, `skin`, `access`) для сервера и клиента. Разойдутся — табличка
   обещает один множитель, сервер начисляет другой.
2. Запрос на стенд: сначала номер существует, потом `access` (`locked` / `forSale` → статус отказа),
   потом занятость и дистанция. Каждый отказ отвечает статусом.
3. Активная тренировка одна на игрока: запись по игроку, пересесть — только слезши.
4. Донатный продукт регистрируется в общем роутере чеков. Номер продукта 0 — не регистрировать:
   чек за незаведённый продукт не подтверждается и Robux не сгорят. Выдача идемпотентна —
   повторный чек за купленное возвращает успех.
5. Начисление: базовый приход × множитель стенда × прочие множители. Множитель стенда умножает
   начисление, а не урон.

## Клиент

- Замки и цены пересчитываются по реплике счётчика и множества покупок, не по пакету: опоздавший
  клиент читает состояние, а не ждёт события.
- На закрытом слоте промпта нет; на некупленном донатном тот же промпт открывает покупку.
- Табличку сверстать шаблоном в месте, клонировать на каждый стенд и писать только тексты и
  видимость иконок. Шаблон не менять из кода: свой `UIScale` для анимации добавлять поверх.
- Табличка вне кадра схлопывается пружиной и выключается целиком (`Enabled = false`): скрытый текст
  не держит глифы в атласе шрифтов. Проверять раз в 0.1–0.2 с: дистанция → проекция → `Z > 0`
  (точка за спиной проецируется внутрь экрана) → запас за краем экрана, иначе мигает на границе.
- Выключать по токену после схлопывания: повторный показ до конца анимации не должен погаснуть.

## Ловушки

- Дистанцию до таблички мерить от персонажа, а не от камеры — и помнить, что после спавна на
  далёкой базе все таблички законно скрыты: «не работает» в тесте часто означает «игрок далеко».
- `table.find` по промптам с дыркой в номерах (стенда нет в месте) молча не находит хвост — искать
  перебором пар.
- В скриншоте Studio табличка за полупрозрачной геометрией может обрезаться по её краю — это
  окклюзия, а не код.

## Чеклист

- [ ] Окно и замки выводятся из счётчика, в профиле только покупки
- [ ] Табличный тест сдвига на весь диапазон счётчика
- [ ] Отказ на закрытый и некупленный стенд со статусом
- [ ] Выдача донатного идемпотентна, продукт 0 не регистрируется
- [ ] Таблички гаснут вне кадра и на время заезда

## Антипаттерны

- Хранить `shift` и открытые слоты в профиле: баланс-проход требует миграции, рассинхрон с счётчиком.
- Двойной сдвиг на ребёрсе, открывшем сдвигающий слот.
- Скин, привязанный к стенду, а не к множителю.
- Считать множитель на клиенте своей формулой.
- Держать все таблички включёнными «на всякий случай» ради простоты.
